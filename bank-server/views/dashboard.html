🎓 CSRF Architecture & Defense Mechanism (IT-30001 Variant 2)

⚡ Root Cause

Browsers automatically attach authenticated session cookies (bank_session_id) to all outgoing requests to http://localhost:3000, even when initiated cross-origin by a third-party malicious website. Without verification of user intent, the server assumes the victim authored the action.

🛡️ Synchronizer Token Mitigation

The server generates an unpredictable, cryptographically random token bound to the victim's session. The legitimate banking form embeds this token. Because cross-origin scripts cannot read the token due to the Same-Origin Policy (SOP), the forged attacker form cannot supply it.

📚 Alternative Mitigations

1. SameSite Cookies: Setting SameSite=Strict or Lax stops ambient cookie transmission on cross-site POSTs.
2. Re-authentication: Demanding password/OTP for sensitive state-changing transactions.
3. Idempotent GET: Ensuring GET requests never perform financial or state mutations.
